# 节令原料保底结算

合作社协调小农户节令原料（芝麻、花生、果仁）的保底收购、浮动分级、
差额结算与争议处理。`fixtures/supply_commitment.json` 保存一条经过脱敏的
业务样例。

## 模块

- `contracts` — 样例信封的最小合同（`schema_version` / `record_id` /
  `domain` / `occurred_at` / `revision` / `source`），既有标识与时间含义不变。
- `domain` — 实体、值对象与状态机：地块、作物批次、承诺（多版本条款）、
  称重、取样、实验室报告、接收、退货、结算单、台账事件、协商、申诉、
  替代去向、成品批次。
- `grading` — 浮动分级与保底价计算。
- `store` — 线程安全的内存仓储，写入按记录标识幂等。
- `service` — 统一入口 `SettlementService`：收货、结算、版本同意、
  减产协商、申诉、总账复算、替代去向、成品追溯，全部带访问控制。
- `loader` — 读取样例并导入服务。

## 数据合同与迁移

schema_version 1 → 2 为纯新增迁移：

- 信封六个字段及其含义不变，`record_id` 等既有标识保留；
- 新增 `parcels` / `crop_batches` / `commitments` 三段业务负载；
- 旧读者（`contracts.load_record`）只读信封，无需任何改动。

以下状态机均随 schema_version 2 引入，旧样例不含这些状态，无需数据迁移；
后续新增状态必须在此登记：

- `VersionStatus`：DRAFT → ACTIVE → SUPERSEDED；DRAFT → REJECTED
- `NegotiationStatus`：PROPOSED → EVIDENCED → AGREED | REJECTED
- `AppealStatus`：FILED → UNDER_REVIEW → UPHELD | ADJUSTED

## 核心规则

**价格（保底 + 浮动分级）**

```
基准价 = 市场参考价（接收时可选）否则保底价
单价   = max(保底价, 基准价 + 等级浮动)
```

保底价是下限；没有市场参考价时向下浮动不生效。水分、杂质超过阈值按
比例扣重（每超 1 个点扣约定百分比），扣重理由写在结算单上给农户看。

**结算单**：每次交付后立即可查，含数量、等级、扣除理由、预计付款日
（接收时间 + 条款约定天数）。实验室更正沿用原批次重新定级，旧结算单
保留历史，差额以补差事件入账。

**收货不变量**

- 称重、取样、实验室更正、部分接收、退货全部沿用原批次标识；
- 同一批次在多站点并发登记时，累计接收不超过实收数量
  （检查与入账在同一锁临界区完成）；
- 同一承诺累计净接收不超过承诺总量，超出部分走替代去向；
- 接收、退货、称重按记录标识幂等，站点重试不重复入账。

**条款版本**：价格或规则变化只能生成 DRAFT 新版本，农户明确同意后
才生效（旧版本转为 SUPERSEDED）；拒绝或未表态时旧版本继续有效。

**减产协商**：洪涝、持续干旱等减产先开协商并提交证据，合作社定案时
把不可抗减免与未履约部分分别记录，履约报告分列实收、退货、减免与
未履约余量。

**总账**：台账只由事件组成（金额符号：正 = 合作社欠农户增加），
任何时候可复算——

```
应付余额 = 尾款合计 + 补差合计 − 预付款合计 − 退货合计
```

申诉裁定补差同样以补差事件入账，复算结果自然包含。

**访问控制**：合作社可见全部；工坊只能查看、登记、追溯自己的采购
关系；农户只能查看自己的结算单与账目、就自己的结算单申诉、对条款
新版本表态。
